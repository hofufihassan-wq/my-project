## التغييرات

- بطاقات الداشبورد: أخضر `rgba(21,62,47,.64)`، وزجاجي `rgba(24,62,78,.54)`، مع نصوص فاتحة وحدود خفيفة وضبابية للخلفية. التخطيط السابق محفوظ.
- عرض الكود: Highlight.js المحلي نفسه، بلا اعتماد جديد. لوحة ألوان مستوحاة من Dark+: الخلفية `#1e1e1e`، الكلمات `#569cd6`، النصوص `#ce9178`، الأرقام `#b5cea8`، الدوال `#dcdcaa`، الخصائص `#9cdcfe`، الأنواع `#4ec9b0` والتعليقات `#8ba878`.
- المحرر textarea الأصلي باقٍ؛ طبقة العرض لا تغيّر القيمة ولا تُصدر أحداث إدخال أو تخزين. تُزامن الخط والتمرير والتحجيم. تعرض HTML وCSS وJavaScript وVue ضمن قواعد Highlight.js المحلية، وليست محلل Vue دلاليًا كاملًا.
- توحيد عرض المصدر في القاموس والشرح والدروس والمختبرين، وترتيب أدوات CSS والأوامر والكونسول، وصقل التقويم والإعدادات. لا تغيير في الملاحظات ومحركات التنفيذ والتخزين أو بيانات الدروس.
- التذييل التقني العام الذي كان يعرض Nuxt UI وVue وTailwind استُبدل بعبارات عربية؛ النصوص التعليمية وحدود الشرح محفوظة.

## الفحوص

فحوص متصفح التطبيق الكامل: 50/50؛ ثم 26/26 للمقربات و4/4 للمعاينة المنتظرة. تشمل 13 قسمًا بالثيمين، الجوال 390px، غياب امتداد أفقي، تلوينًا حقيقيًا، تطابق النص والخط والعرض بين المحرر والطبقة، وخلفية تحرير شفافة، وتحديد النص وحفظ المسودة بعد إعادة التحميل. فحص الداشبورد الموجود 29/29، بما فيه الثيمات الخمسة والتنقل ولوحة المفاتيح وتقليل الحركة.

المحاولة الأولى أثبتت أيضًا أن محاكاة Vue في اختبارات البيانات لا تعرّف `directive`. أضفنا حارس تسجيل العرض؛ نجحت اختبارات البيانات 15/15 وJSON 9/9 بعدها. كذلك صححنا تعارض خط pre العام مع خط المحرر وخلفية المحرر القديم في القاموس. لم نعدّل شروط الاختبارات الأصلية لإخفاء إخفاق. إعداد ffmpeg في محاولة إعادة CSS الأولى كان يشير لمسار غير موجود؛ أعيد الفحص باستخدام المسار المثبت الصحيح.

التقارير الأصلية للمحاولتين محفوظة بجوار نتائج الإعادة، وليست تقريرًا موحدًا مصطنعًا يدّعي مرور كل شيء من أول تشغيل.

## حماية المحاكي والبيانات

مقارنة PNG متطابقة بالبايت 4/4 للمحاكي: الثيمان، 1440px و390px. ملفات القاموس والمنهج القديم والدروس المتقدمة والتخزين والمحاكي ومشغل المعاينة وأدلته متطابقة بالبايت مع «قبل». الأجزاء المنطقية في ملفات الشرح والدروس ومختبري CSS وJS قبل `template:` متطابقة أيضًا. التعديلات في app.js تسجيل توجيهي عرض فقط، لا تعديل دوال التطبيق.

فحص المحاكي الشامل 32/33 في محاولتين: جميع التجارب الخمس عشرة والتحكم والعزل وعرض الجوال نجحت، لكن التقاط تنبيه خطأ قصير سجّل RMS=0. الفحوص الصوتية الخمسة نفسها منفردة نجحت 5/5 قبل وبعد، بصوت محيطي حقيقي، كتم مستقل، حجم صفر صامت وتنبيه خطأ غير صفري. هذه قرينة على حساسية توقيت القياس، وليست إثباتًا لجودة سمعية أو نجاح 33/33؛ لا تغيير للصوت قبل مراجعة مستقلة إن استمرت الملاحظة.

الفحص التاريخي الأقدم الذي يقارن ملفات المحاكي حرفيًا بإصدار `5d05acf` كان له إخفاق معروف قبل التصميم؛ لا يُنسب اختلافه عن النسخة المعتمدة لهذه المرحلة.

## التسجيل والخصوصية

فيديو متصل 112.2 ثانية، H.264/yuv420p، 1440×1000، MP4 بحجم 7,667,630 بايت؛ تحويل صيغة كامل بلا قص. بلا مسار صوتي؛ أدلة الصوت مستقلة. التصفح بحساب محلي معزول، والمشروع الظاهر في الفيديو عينة مراجعة اصطناعية. لا جلسة مستخدم أو مفاتيح أو ملفات اعتماد في واجهة الموقع المصوّرة. تمت معاينة صور الأقسام ولوحة إطارات التسجيل، وفحص بيانات الملفات الوصفية؛ لا ادعاء بفحص سري شامل للمستودع كله.

المحاولة الأولى للتسجيل توقفت لأن أداة الالتقاط اختارت مصطلحًا برمجيًا وتركت قائمة البحث مفتوحة؛ صححنا مسار التسجيل ليختار نتيجة البحث بالنقر الطبيعي، ثم أُعيد التسجيل كاملًا من البداية. لم نقص الجزء المتعثر من تسجيل واحد لنخفيه. في التسجيل النهائي مثال Flex يعرض رسالة احتياج سياق صحيحة، وصور قسم المعاينة تعرض زر HTML المستقل؛ انتظار ظهور الزر مطلوب قبل التصوير، بدل الاكتفاء بإشارة preview_ready.

## التحقق من GitHub

الموصل أكد أن المستودع Private. تُرفع الملفات إلى فرع التصميم وحده؛ لا main ولا دمج ولا نشر ولا خدمة مدفوعة.

التحقق من وجود ملفات الفرع وبصماتها عن طريق Git وGitHub ممكن، لكنه لا يثبت عرض الصور أو تشغيل الفيديو في واجهة GitHub. متصفح البيئة بلا جلسة GitHub، والصفحة الخاصة أعادت HTTP 404، وأدوات التحكم بمتصفح مشترك غير متاحة (`capabilities: []`، ولا أداة `cua_repl.js`). لذلك يظل اعتماد التسليم البصري معلقًا حتى فتح التقرير من جلسة GitHub مخوّلة والتأكد من عرض الوسائط، أو اعتماد تنزيل MP4 الخاص كبديل. لم تُستخدم خدمة استضافة عامة للتحايل على الخصوصية.
