# فحص الأمان والخصوصية قبل النشر

## النطاق والنتيجة

فُحصت حالة Git المتاحة بعد fetch لكل الفروع، عند نقطة التجهيز `a97a5fb`، قبل نشر الموقع. Gitleaks 8.30.0 من المستودع الرسمي؛ تحقق SHA-256 للأرشيف `79a3ab579b53f71efd634f3aaf7e04a0fa0cf206b7ed434638d1547a2470a66e`. التقارير تحجب القيم ولا تنشر محتوى أسرار محتملة.

|الفحص|النتيجة|
|---|---|
|تاريخ تغييرات Git عبر كل المراجع|لا أسرار مكتشفة؛ 77 Commit ذات تغييرات فُحصت، مقابل 84 Commit إجماليًا مع Commits الدمج|
|قراءة جميع blobs القابلة للوصول|2,754 blob؛ 1,606 نصية قُرئت كاملة، و1,148 ثنائية|
|Gitleaks على النصوص الكاملة ورسائل Commits|لا أسرار مكتشفة، نحو 41.82 MB|
|المحتوى المتتبع الحالي|3,149 ملفًا قبل ملفات التجهيز الجديدة؛ فحص مع فك الأرشيفات والتشفير المدعوم، لا أسرار مكتشفة|
|الأرشيفات التاريخية|ثلاثة ZIP فريدة موجودة أيضًا في الملفات الحالية، فُحصت محتوياتها بفك حتى 3 طبقات، لا أسرار مكتشفة|
|مطابقة تعيينات كلمات مرور إضافية|حالتان فقط، كلتاهما CSS selector `[type=password]` في LinkeDOM المثبت، وليستا كلمة مرور|

الأدلة المحجوبة تحت [evidence/security](evidence/security/). يشمل CI المستقبلي الفحص نفسه للمراجع والنصوص الكاملة والأرشيفات، مع فحص الملفات الجديدة بعد commit. كل القياسات أعلاه مرتبطة بنقطة الفحص المحددة؛ نتائج CI للـCommit الجديد تفحص الزيادة التالية.

## مسألة الخصوصية المفتوحة

المستخدم اعتمد أن المستودع أصبح Public، لكن الإذن السابق لأسماء مؤلفي Git وبريدهم كان للنقل الخاص فقط. لذلك لم نعتبر ظهور هذه البيانات العامة موافقةً تلقائية على نشرها. لا نسجل عناوينها الكاملة أو أسماءها في هذا التقرير العام.

الخيارات: قبول المالك صراحة بقاء بيانات المؤلفين في التاريخ العام، أو اختيار معالجة خصوصية مختلفة قبل نشر الموقع. جعل المستودع Private يحفظ التاريخ، ويمكن أن تعمل Pages مع مستودع خاص؛ لكنه يخالف الحالة العامة المعتمدة حاليًا إن غُيّر دون موافقة. إزالة metadata من التاريخ العام فعليًا تحتاج إعادة كتابة ونظرًا لكونها محظورة في طريقة العمل الحالية **لم تُنفذ**. ملف mailmap أو Commit جديد لا يزيل العناوين من Commits القديمة، فلا يُقدّم كإصلاح وهمي.

أُنشئ دمج التجهيز المحلي قبل إغلاق مراجعة الهوية، دون تعديل بيانات المؤلفين القديمة. تستخدم Commits التجهيز الآلية التالية هوية غير شخصية من نطاق `.invalid` المحجوز، دون استبدال مؤلفي أي Commit أصلية أو تغيير إعدادات المستودع. لا force push، ولا حذف لتاريخ أو فروع أو ميزات أو بيانات تعلم.

**يبقى نشر الإنتاج معلقًا على قرار خصوصية هذا التاريخ وموافقة main وربط الحساب.** هذا اكتشاف خصوصية، لا اكتشاف مفتاح API فعّال أو كلمة مرور خدمة.

## حدود الفحص

الفحص المعتمد أنماط وكشف ترميزات وأرشيفات، ولا يثبت غياب كل سر ممكن. لم تُجر اختبارات صلاحية لأي مفتاح خارجي ولم تُرسل القيم لأي خدمة تحقق. الصور والفيديو الثنائية في كامل التاريخ ليست OCR مفحوصة صورة صورة؛ صور المعاينة الأخيرة بملفات مستخدم تجريبية جديدة، ولا توزع docs أو الصور التاريخية ضمن dist.

البيانات المسماة author/committer عولجت بشكل منفصل عن كود الموقع. بيانات تراخيص المكتبات العامة تُحفظ كما هي. npm audit يغطي lockfiles المحددة، ولا يعد شهادة تدقيق لكل مكتبة vendor مثبتة؛ جرى التحقق من بصمات 45 أصلًا/ترخيصًا وتشغيل اختبارات العزل والتنفيذ الموجودة.

لا يوزع البناء Git أو ZIP أو node_modules أو docs أو الاختبارات أو ملفات الاعتماد. لم تكتشف مفاتيح أو كلمات مرور فعلية ضمن النطاق المفحوص، فلا ندّعي إجراء تدوير لمفاتيح لم توجد.

## إعادة الفحص

في CI: `bash scripts/ci-secrets.sh`. ينزل Gitleaks بإصدار وبصمة ثابتين، ويقرأ Git والملفات المتتبعة فقط، ثم النصوص والأرشيفات التاريخية. تحفظ JSON/logs المحجوبة، ولا تُرفع نسخ الأرشيفات أو المصدر مع تقارير الفحص. مراجعة metadata الشخصية خطوة بشرية منفصلة، وليست علامة نجاح أمنية شكلية.
