# خطة التراجع مع بقاء الكود وبيانات التعلم

لم يوجد بعد نشر Cloudflare إنتاجي متحقق منه؛ لا نسمّي Preview أو main القديم «آخر إصدار مستقر» افتراضًا. يبدأ سجل الاستقرار بعد أول نشر ناجح وفتح رابطه واجتياز القبول.

## عند وجود إنتاج سابق مستقر

1. أوقف الدمج مؤقتًا وسجّل deployment ID والـCommit والرابط والعطل، دون حذف النشر الفاشل أو سجل Git.
2. في Cloudflare Pages ← المشروع ← Deployments، اختر نشر إنتاج سابقًا ناجحًا ومختبرًا ← قائمة النقاط ← Rollback to this deployment. راجع الهدف قبل التأكيد.
3. افتح **رابط الإنتاج نفسه**، وتحقق من release-manifest وملفات JS والدروس والمشاريع والمحاكي والحفظ. سجّل وقت التراجع والهدف ونتائج الفحص.
4. يتغير إصدار الملفات، ولا تُمسح بيانات المتصفح ولا تُستورد نسخة تقدم قديمة تلقائيًا. صدّر بياناتك قبل أي معالجة بيانات لاحقة.
5. أصلح سبب العطل في فرع مستقل، وافتح PR واختبر وراجع قبل main. لا force push ولا reset لإخفاء الـCommit الفاشل. التراجع المؤقت في Cloudflare لا يغير main؛ دفعة main التالية قد تعيد النشر، فلا تدمج قبل معالجة السبب.

فقط النشرات **الإنتاجية** الناجحة أهداف rollback بحسب Cloudflare؛ Preview ليست هدفًا صالحًا. لا يكفي وجود build ناجح دون فحص الرابط ليكون لدينا مرجع استقرار موثق.

## عندما يكون أول نشر هو الفاشل

لا يوجد إصدار إنتاج سابق للتراجع إليه. احتفظ بسجله، ولا تستبدله بنسخة قديمة غير مفحوصة لمجرد أنها main. جهّز إصلاحًا من المرشح المعتمد واختبره، ثم انشره بعد المراجعة. إذا لزم إيقاف الوصول أو تعطيل نشر آلي، وضح الإعداد المطلوب للمالك أولًا؛ لا تحذف مشروعه أو تغيّر إعداداته بصمت.

## التراجع بالكود

استخدم Commit تصحيحًا أو git revert في **فرع إصلاح** ثم اختبارات وPR، لا إعادة كتابة التاريخ. عند التراجع عن merge يحتاج git revert تحديد parent الصحيح؛ افحص بنية merge ولا تنسخ أمرًا عامًا دون معرفة الـCommit. لا تنفذ التراجع مباشرة على main خارج مسار المراجعة.

يجب فحص توافق إصدار البيانات في المتصفح مع الكود الذي ستعود إليه. إذا كان إصدار مستقبلي غير متوافق، استخدم خطة ترحيل مستقلة تحفظ النسخة الكاملة أولًا؛ rollback الموقع ليس rollback بيانات المستخدم.

## سجل النشرات

حدّث DEPLOYMENTS.json بعد كل محاولة فعلية: commit، deployment ID، URL، وقت البناء والنشر، نتيجة فتح الموقع واختبارات القبول، وسبب التراجع وهدفه إن وقع. سجلات Cloudflare وGit ونتائج CI تكمل بعضها، ولا تُحذف الإخفاقات. لا توضع أسرار الحساب أو نسخ تقدم الأشخاص في السجل العام.
