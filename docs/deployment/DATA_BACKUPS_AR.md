# نسخ الكود ونسخ بيانات التعلم

|النسخة|ما تحفظه|ما لا تحفظه|
|---|---|---|
|Git وCommits الموقع|الكود والمنهج والأصول وإعدادات البناء|التقدم والمسودات والملاحظات المحفوظة في متصفح المستخدم|
|نشر Cloudflare سابق|ملفات الموقع المبنية لذلك النشر|بيانات المتصفح، ولا يعيدها عند rollback|
|النسخة الشاملة من الإعدادات|التعلم والمشاريع وبيانات التنظيم والقاموس والتدريب والمسودات والثيم وإعدادات المحاكي المدعومة|كلمات مرور حسابات أو مزامنة عبر الأجهزة؛ لا يوجد نظام حسابات هنا|
|استرجاع الاستيراد المحلي|حالة محلية احتياطية للعملية وفق النظام الحالي|نسخة سحابية دائمة أو حماية من مسح كل بيانات المتصفح|

## نقل التقدم من localhost أو رابط قديم

1. افتح **العنوان القديم نفسه** وفي المتصفح وملف المستخدم اللذين كان فيهما تقدمك. لا تمسح بيانات المتصفح.
2. الإعدادات ← **تصدير النسخة الشاملة**، واحفظ JSON في مكان آمن خارج مجلد الموقع. حافظ على نسخة إضافية خاصة إن أمكن.
3. افتح الرابط الجديد الذي تم التحقق منه. ظهور تقدم فارغ أول مرة طبيعي؛ اختلاف النطاق أو البروتوكول أو المنفذ يعني origin مختلفًا.
4. إذا وجدت بيانات مهمة على الرابط الجديد، صدّر نسخته الشاملة أولًا. **الاستيراد استبدال متحقق منه وليس دمج سجلين.** لا تفترض أنه يجمع تقدم موقعين.
5. الإعدادات ← استيراد النسخة الشاملة ← اختر الملف ← راجع رسالة الاستبدال ووافق. لا ترفع ملفك إلى GitHub أو Issues أو التقارير العامة؛ قد يحتوي ملاحظات وبيانات شخصية.
6. راجع الدروس والمشاريع والمسودات والثيم، ثم أغلق المتصفح وافتح الرابط نفسه. جرّب تصدير نسخة جديدة من العنوان الجديد.
7. احتفظ بالملف الأصلي والعنوان القديم حتى تتأكد من سلامة النقل. عند فشل الاستيراد لا تحاول تعديل JSON عشوائيًا أو مسح التخزين؛ حافظ على الأصل واستعمل أدوات الاسترجاع المتاحة.

النسخ القديمة المتوافقة تبقى مدعومة، والملف التالف يرفض دون استبدال البيانات. إعادة فتح الموقع بعد الاستيراد لا تشغّل كود المستخدم تلقائيًا. اختبرنا الانتقال بين origin مختلفين ببيانات تجريبية، وبقي الاختبار على رابط الإنتاج الحقيقي معلقًا قبل النشر.

التخزين محلي لكل origin، بحد مخزن التعلم 2 MiB والنسخة الشاملة 8 MiB. تغيير pages.dev إلى نطاق مخصص مستقبلًا يحتاج نقلًا جديدًا بالطريقة نفسها. الوضع الخاص أو حذف التخزين أو منع حفظ بيانات الموقع قد يفقد التقدم؛ مؤشر الحفظ يوضح الإخفاق ولا يجعل ملف Git نسخة بيانات للمستخدم.

## سياسة النسخ والتحديث

- صدّر النسخة الشاملة قبل نقل النطاق أو الاستيراد أو تحديث رئيسي، وبعد كل فترة تعلم مهمة. يختار المستخدم مكان حفظه الخاص؛ لا يجمع الموقع النسخ تلقائيًا في خادم.
- لا يُنفذ في هذه المرحلة نسخ سحابي لبيانات الأشخاص أو تسجيل دخول أو رموز ستة أرقام. أي مزامنة مستقبلية مشروع مستقل يحتاج خصوصية ومصادقة وخطة ترحيل.
- يحتفظ Git بتاريخ الكود، ويمكن لمالك المشروع عمل clone/mirror ونسخة خاصة خارج GitHub دوريًا. سجلات CI قصيرة الأجل ليست نسخة كود دائمة.
- تحديث ملفات الموقع أو التراجع عنها لا يستدعي حذف localStorage. أي تغيير مستقبلي في مخطط البيانات يجب أن يمر باختبار توافق واستيراد واسترجاع قبل main.
