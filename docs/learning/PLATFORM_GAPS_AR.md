## فجوات منصة حقيقية لكنها ليست أولوية تعليمية تلقائية

- **المزامنة متعددة الأجهزة والحسابات غير موجودة في البنية المفحوصة.** الحفظ الحالي محلي ويدعم التصدير والاستيراد؛ لا ينبغي تسويقه كسحابة. إضافة حسابات أو backend تحتاج قرارًا مستقلًا بشأن الخصوصية والتكلفة والنسخ الاحتياطي، وليست شرطًا لبدء تحسين التعلم المحلي.
- **الروابط الدائمة وسجل التنقل الداخلي غير مكتملين:** appMode لا ينشئ سجل صفحات أو Router؛ يصعب مشاركة رابط درس محدد واستعادته مباشرة. هذا قيد وظيفي معروف سابق، منفصل عن الحركة البصرية، ولم نغيّره هنا.
- **الشرح المحلي ليس مساعدًا دلاليًا عامًا.** تحسينه ممكن عبر أمثلة وتفسير أخطاء محددة وربطه بالمفاهيم؛ لا نحتاج افتراض خدمة ذكاء اصطناعي مدفوعة أو استبدال المحلل كي نبدأ.
- **بيئة التنفيذ ليست IDE متعدد الملفات وبناء حزم كاملًا.** دعم Vue أو SFC المحلي الموجود لا يعني دعم كل إطار وحزمة. ليست إعادة كتابة المحرر أولوية قبل وجود تمارين وأهداف تعلم تستلزمها.

## خطة تعليمية تدريجية مقترحة

1. **حزمة إثبات صغيرة:** اعتماد 6–8 تمارين سلوكية JavaScript مرتبطة بدروس موجودة، مع حالات نجاح وفشل وحدود تنفيذ واضحة. يعرض الطالب ما فُحص وما لم يُفحص. لا تعديل للمحاكي أو البيانات الحالية دون خطة توافق واختبارات.
2. **تنوع واسترجاع:** إضافة أنشطة بديلة للمفاهيم المستهدفة وربطها بالمراجعات الحالية، مع تلميحات تدريجية وسجل محاولات متوافق مع النسخ الاحتياطي القديمة.
3. **مهارات ومشروع ثانٍ:** عرض الأدلة بدل عداد اكتمال وحده، ثم مشروع جديد يستخدم المهارات نفسها في سياق مختلف.
4. **توسعة باعتماد منفصل:** التوجيه الاختياري، مسارات TS/Nuxt، الروابط الدائمة أو المزامنة حسب حاجة الاستخدام؛ ليست جميعها جزءًا تلقائيًا من المرحلة الأولى.

**قراري المقترح للمرحلة التالية:** البدء بالتمارين القابلة للفحص وبنك أسئلة متنوع، لا مزيد من إعادة التلوين أو إضافة لوحة إحصاءات قبل وجود أدلة تعلم جديدة. يُعتمد النطاق ومعايير التقييم أولًا، ثم التنفيذ في فرع مستقل؛ هذا التقرير لا ينفّذ تلك الميزات.
